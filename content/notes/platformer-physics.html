Gravity, jumping, and landing — the side-view version of movement. Requires a CharacterBody2D player and something solid to stand on (TileMapLayer or StaticBody2D platforms).

#Setup checklist

  1. Player scene is a CharacterBody2D with Sprite + CollisionShape2D (CharacterBody2D).
  2. Input Map has move_left, move_right, and jump (Space) — Project → Project Settings → Input Map.
  3. The floor has collision the player's mask can see (TileMapLayer → Making tiles solid (collision)).

#The complete platformer script

extends CharacterBody2D

@export var speed = 300.0
@export var jump_velocity = -400.0   # negative = up! (y grows downward in 2D)
@export var gravity = 1200.0

func _physics_process(delta):
	# 1. Gravity — pull down every frame we're in the air
	if not is_on_floor():
		velocity.y += gravity * delta

	# 2. Jump — only when standing on something
	if Input.is_action_just_pressed("jump") and is_on_floor():
		velocity.y = jump_velocity

	# 3. Left/right
	var direction = Input.get_axis("move_left", "move_right")  # -1, 0, or 1
	velocity.x = direction * speed

	move_and_slide()

Line by line:

  • velocity.y += gravity * delta — gravity is an acceleration: it adds a bit of downward speed each physics frame. Skipping * delta makes gravity absurdly strong.
  • is_on_floor() — true right after move_and_slide() lands the body on something below it. This is the whole "can I jump?" check.
  • is_action_just_pressed (not is_action_pressed) — jump on the press, not while held, or the player pogo-sticks (Movement and Input → Detecting a single press (not held)).
  • jump_velocity is negative — in Godot 2D, y increases downward. Up is minus. Every "my jump goes down" bug is a missing minus sign.
  • Input.get_axis(a, b) — returns -1 when a is held, +1 when b is held, 0 for neither/both. One line instead of two ifs.

#Tuning the feel

All three exports are live-tunable in the Inspector while the game runs (change them in the Remote scene tab):

Feels...Change
Floaty, moon-like↑ gravity (try 2000)
Jump too short↓ jump_velocity (more negative, try -550)
Sluggish↑ speed

Rule of thumb: big gravity + big jump velocity = snappy arcade jump. Small values of both = floaty. See Juice and Game Feel for what to add once it moves right.

#Nice-to-haves (only if the basic jump works)

Variable jump height — release early to jump shorter, hold for full height:

	# add after the jump code, inside _physics_process
	if Input.is_action_just_released("jump") and velocity.y < 0:
		velocity.y *= 0.4   # cut the rest of the upward motion

Coyote time — a tiny grace period to jump just after walking off a ledge. Makes the game feel fair instead of strict:

@export var coyote_time = 0.1   # seconds of grace
var coyote_timer = 0.0

func _physics_process(delta):
	if is_on_floor():
		coyote_timer = coyote_time
	else:
		coyote_timer -= delta
		velocity.y += gravity * delta

	if Input.is_action_just_pressed("jump") and coyote_timer > 0:
		velocity.y = jump_velocity
		coyote_timer = 0.0

	var direction = Input.get_axis("move_left", "move_right")
	velocity.x = direction * speed
	move_and_slide()

(This replaces the is_on_floor() jump check — the timer covers both cases: on the floor it's always fresh, off a ledge it's briefly still valid.)

One-way platforms — jump up through, stand on top: on the platform's CollisionShape2D, check One Way Collision in the Inspector. Works on tiles too (in the tile's Physics properties).

⚠️"is_on_floor() is always false"

Two usual causes: (1) gravity is applied but move_and_slide() never runs (it must be called every frame — it's what updates the floor check), or (2) you're setting position directly instead of using velocity + move_and_slide(). Move only through velocity.
