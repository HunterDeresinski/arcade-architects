Difficulty: ⭐⭐ moderate · Payoff: ⭐⭐⭐ high · Time: 45 minutes

A character speaks, text types out one letter at a time, you press a key to continue. This unlocks narrative games — and for Girls Who Game specifically, it's the bridge from the Twine work students already know how to design to the engine they're learning this week.

💡You already know how to write these

If you've made a Twine game, you've written branching dialogue. This note is only about displaying it in Godot. The hard part — writing something worth reading — you've already practised.

#The dialogue box scene

Scene → New Scene → CanvasLayer, save as dialogue_box.tscn.

DialogueBox        (CanvasLayer)   Process Mode: Always
└── Panel           (Panel)         anchored bottom, ~200px tall
    ├── Portrait     (TextureRect)
    ├── SpeakerName  (Label)
    ├── Text         (RichTextLabel)
    └── Indicator    (Label)  "▼"   ← the blinking "press to continue"

Use a RichTextLabel, not a Label — it supports [b]bold[/b], [color=red]red[/color], and shaky text, and it wraps properly. Check Fit Content and turn on BBCode Enabled.

#The typewriter effect

Text appearing one character at a time is the whole feel of dialogue. It's five lines.

extends CanvasLayer

signal finished

@export var characters_per_second = 40.0

var lines: Array = []
var current_line = 0
var is_typing = false

func _ready():
	hide()

func start(dialogue_lines: Array):
	lines = dialogue_lines
	current_line = 0
	show()
	get_tree().paused = true
	show_line()

func show_line():
	var entry = lines[current_line]
	$Panel/SpeakerName.text = entry.get("name", "")
	$Panel/Text.text = entry["text"]
	$Panel/Text.visible_ratio = 0.0
	$Panel/Indicator.hide()
	is_typing = true

	var duration = entry["text"].length() / characters_per_second
	var tween = create_tween()
	tween.tween_property($Panel/Text, "visible_ratio", 1.0, duration)
	await tween.finished

	is_typing = false
	$Panel/Indicator.show()

visible_ratio is the trick — a RichTextLabel property from 0 to 1 controlling how much of the text is shown. Tween it and you have a typewriter with no per-character loop (Tweens).

Set the CanvasLayer's Process Mode to Always or the tween freezes with the paused game (Pause Menu).

#Advancing, and skipping

func _unhandled_input(event):
	if not visible or not event.is_action_pressed("ui_accept"):
		return

	if is_typing:
		# first press: skip to the end of this line
		$Panel/Text.visible_ratio = 1.0
		is_typing = false
		$Panel/Indicator.show()
	else:
		next_line()

func next_line():
	current_line += 1
	if current_line >= lines.size():
		close()
	else:
		show_line()

func close():
	hide()
	get_tree().paused = false
	finished.emit()

The skip-on-first-press behaviour is not optional. Players who read faster than 40 characters a second will mash the key, and without it they'll blow straight past three lines of your story.

#Triggering it

An Area2D the player walks into, or an interact press near an NPC:

extends Area2D

@export var speaker = "Old Wizard"
@export_multiline var line_1 = "You again."
@export_multiline var line_2 = "The bridge is out. You'll have to find another way."

var used = false

func _on_body_entered(body):
	if used or not body.is_in_group("player"):
		return
	used = true
	Global.dialogue.start([
		{"name": speaker, "text": line_1},
		{"name": speaker, "text": line_2},
	])

@export_multiline gives you a proper multi-line text box in the Inspector — the writer on the team can edit dialogue without opening a script. That's the single most useful line in this note for a mixed-skill team.

Make the dialogue box an autoload so any scene can call it.

#Writing dialogue in a separate file

Once you have more than a few conversations, put them in JSON instead of scattering them across scenes. Create res://dialogue.json:

{
  "wizard_intro": [
    {"name": "Wizard", "text": "You again."},
    {"name": "Wizard", "text": "The bridge is out."},
    {"name": "You", "text": "...I noticed."}
  ],
  "sign_1": [
    {"name": "", "text": "DANGER: LAVA"}
  ]
}
var all_dialogue = {}

func _ready():
	var f = FileAccess.open("res://dialogue.json", FileAccess.READ)
	all_dialogue = JSON.parse_string(f.get_as_text())
	f.close()

func play(key):
	start(all_dialogue[key])

Now the whole script of your game lives in one readable file. Global.dialogue.play("wizard_intro") from anywhere. This is how real narrative games do it — reading from res:// is fine because you never write to it (High Scores That Persist explains why writing there fails).

#Branching choices (the Twine part)

# an entry can offer choices instead of just continuing
{"name": "Wizard", "text": "Will you help?", "choices": [
	{"text": "Yes.",  "goto": "wizard_accept"},
	{"text": "No.",   "goto": "wizard_refuse"}
]}
func show_choices(choices):
	$Panel/Indicator.hide()
	for choice in choices:
		var b = Button.new()
		b.text = choice["text"]
		b.pressed.connect(func(): pick(choice["goto"]))
		$Panel/Choices.add_child(b)

func pick(key):
	for c in $Panel/Choices.get_children():
		c.queue_free()
	play(key)

"goto" naming another key in the JSON is exactly a Twine passage link. Put the Buttons in a VBoxContainer so they arrange themselves (Label and CanvasLayer).

#Polish that matters

  • A blip sound per character. Play a short click every few letters — it's the difference between text and a character talking. Keep it quiet and vary pitch_scale slightly.
  • A portrait that changes with the speaker. One TextureRect, swap the texture per line.
  • BBCode for emphasis: "That was [shake rate=20]terrifying[/shake]." RichTextLabel animates it for free.
  • Blink the ▼ indicator with a looping tween so players know to press something.
