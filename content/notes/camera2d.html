How to make the screen follow the player. The moment a team's level (TileMapLayer) is bigger than one screen, they need this. Zero code required for the basic version.

#The zero-code version

  1. Open your Player scene (CharacterBody2D).
  2. Add a Camera2D as a child of the Player.
  3. Done. A Camera2D in the scene tree is active automatically, and because it's a child, it goes wherever the player goes.
Player          (CharacterBody2D)
├── Sprite
├── Shape       (CollisionShape2D)
└── Camera      (Camera2D)         ← screen now follows the player
🗒️Only one camera wins

If two Camera2Ds are active, the most recently entered one takes over. If the view snaps somewhere weird, search the scene tree for a second camera (often left in Main from an earlier experiment).

#Stop showing the void: limits

Without limits, the camera happily shows the empty gray space past the edge of your level. Clamp it, in the Inspector under Limit:

  • Left: 0, Top: 0 (if your level starts at the origin)
  • Right: level width in pixels, Bottom: level height in pixels

How to find the numbers: level width = tiles across × tile size. A 100-tile-wide level of 16px tiles → Right = 1600. Or click the far edge of your level in the editor and read the position in the toolbar.

The camera now stops at the edges while the player walks up to them — like Mario.

#Smoothing (the difference between "camera" and "glued to head")

Inspector → Position Smoothing → Enabled ✓. The camera now eases toward the player instead of tracking it rigidly.

  • Speed ≈ 5 = dreamy, ≈ 10 = default-ish, ≈ 15+ = tight.
  • This one checkbox is a big Juice and Game Feel win.
⚠️Smoothing + limits jitter

If the camera stutters at level edges, also check Limit → Smoothed ✓.

#Platformer camera recipe

Side-scrollers (Platformer Physics) need more than "glued to the player" — jumping makes a rigid camera bounce nauseatingly. Three Inspector tweaks fix it:

1. Drag margins — stop tracking every jump. Inspector → Drag:

  • Vertical Enabled ✓, then set Top Margin ≈ 0.7 and Bottom Margin ≈ 0.2.
  • Now the camera ignores small vertical moves (normal jumps stay inside the margin box) and only scrolls when the player actually climbs or falls far. This one change is 80% of a good platformer camera.
  • Leave Horizontal Enabled off — you do want tight left/right tracking.
  • Turn on Editor → Draw Drag Margin ✓ to see the box while tuning.

2. Offset the view upward. Players care about what's ahead and above, not the ground under their feet. Inspector → Offset → y = -40 (or so) shifts the view up.

3. Smoothing on, as in the section above — Speed ≈ 8 for platformers.

Look-ahead (optional, scripted): shift the camera toward where the player is heading so they can see what's coming. Attach to the Camera2D:

extends Camera2D

@export var look_ahead = 80.0    # pixels ahead of the player
@export var shift_speed = 3.0    # how fast the view slides over

func _process(delta):
	var player = get_parent()    # camera is a child of the player
	var target_x = 0.0
	if player.velocity.x != 0:
		target_x = look_ahead * sign(player.velocity.x)
	offset.x = lerp(offset.x, target_x, shift_speed * delta)
  • sign() — returns -1 or 1, so the offset flips with the run direction.
  • lerp() — eases the offset over instead of snapping it. Turn shift_speed down if direction changes feel swimmy.
  • If you also used the screen-shake script below, put both in one script — they both write to offset (shake wins while shaking is fine: add the shake to offset.y instead of overwriting).

Full platformer settings at a glance: child of Player · Limits set · Position Smoothing ✓ (8) · Drag Vertical ✓ (0.7 / 0.2) · Offset y −40.

#Zoom

Inspector → Zoom. (2, 2) = twice as close (pixel-art games usually want this), (0.5, 0.5) = zoomed out. Keep x and y equal.

For pixel art that looks blurry when zoomed: Project Settings → Rendering → Textures → Default Texture Filter → Nearest.

#Screen shake (tiny code, big payoff)

The one camera feature worth scripting. Attach to the Camera2D:

extends Camera2D

var shake_amount = 0.0

func _process(delta):
	if shake_amount > 0:
		offset = Vector2(randf_range(-shake_amount, shake_amount),
						 randf_range(-shake_amount, shake_amount))
		shake_amount -= 60 * delta   # calm down over time
	else:
		offset = Vector2.ZERO

func shake(amount = 8.0):
	shake_amount = amount

Call it from anywhere via the player, e.g. in a hit handler (Area2D):

func _on_hurtbox_body_entered(body):
	$Camera.shake(10)
	# ...damage code...
  • offset shakes the view without touching the camera's real position — limits and following keep working.
  • Bigger amount = harder hit. 4 for a coin, 10 for damage, 20 for an explosion. More ideas in Juice and Game Feel.

#Fixed camera (single-screen games)

Making a one-screen arcade game (like Day 1's)? You don't need a Camera2D at all — the default view is the screen. Only add one when the level outgrows the window.
