A 5-day game development camp modeled on CU Boulder's Tiny Game Studio (ATLS 4060) philosophy: tiny games — short games with tight technical constraints, built quickly, around a single idea. Instead of Bitsy/PuzzleScript/Pico-8, campers use one engine (Godot 4) and progress from guided template games to a fully original team game presented on the final day.

Structure: Each day = Teaching Block (~3 hrs, required) + Open Studio (optional work time) Team size: 3–4 per team

ℹ️This is the overview. The full lesson-by-lesson curriculum, student references, and instructor notes live in the Curriculum Map.

#Camp Goals

By Friday, every camper can:

  1. Navigate Godot: scenes, nodes, the editor, running a game
  2. Read and modify GDScript (variables, signals, _process, simple conditionals)
  3. Build 1–3 tiny games from tutorials/templates
  4. Design within constraints: scope a game idea down to one mechanic
  5. Ship one original team game and present it at the Friday Arcade Showcase

The Tiny Game Rules (post these on the wall all week):

  • One core idea. If you can't say it in one sentence, it's too big.
  • Playable in under 3 minutes.
  • Done is better than perfect. Cut features, not deadlines.

#What students are building

Dodge the Creeps: a character you move with arrow keys, enemies that fly in from the edges, survive as long as you can. It covers: scenes, nodes, AnimatedSprite2D, GDScript, movement, signals, collision, and spawning with timers.

#Open Studio (optional)

HUD (score + start button), background color, background music, death sound, stretch goals. See the Stretch Goals section in Day 1 - Meet Godot.

#Day 2 (Tue) — Make It Yours (Remix)

📓 Full lesson + student reference: Day 2 - Make It Yours

Goal: Move from following code to changing code. Game #2 = a personal remix of Game #1.

#Teaching Block

0:00–0:15 — Warm-up: read the code Project a chunk of yesterday's player script. Ask: "What happens if I change this number? Delete this line?" Change it live. Normalize breaking things.

0:15–0:45 — Mini-lessons (pick 3, ~10 min each)

  • Swapping sprites and sounds (importing assets, AnimatedSprite2D)
  • Variables as game-feel dials: speed, spawn rate, scale
  • Adding a new rule with if (e.g., touching a star = +10 points)
  • Timers and signals (e.g., speed up every 10 seconds)

0:45–2:30 — Remix sprint Each camper (or pair) remixes Dodge the Creeps into a new game. Require at least 3 changes across 2 categories:

  • Look/sound: new art, new audio, new title
  • Rules: new pickup, lives, win condition, second enemy behavior
  • Feel: speed, gravity, spawn rates, screen size

Remix prompts for the stuck: "the player is a fish," "dodging is collecting," "the game speeds up forever," "two-button game only."

2:30–3:00 — Playtest carousel Rotate seats every 3 minutes, play each other's remixes, leave one sticky note: Something you liked + One question.

#Open Studio (optional)

Keep remixing, or start the optional micro-game challenge: a one-screen, one-button game from scratch (this is the path to "3 games").

#Day 3 (Wed) — Design Day: Pitch, Teams, Prototype

📓 Full lesson + student reference: Day 3 - Design Day

Goal: Shift from learning the engine to making something original. Leave with teams, a locked one-sentence pitch, a paper prototype, and an empty-but-set-up Godot project.

#Teaching Block

0:00–0:30 — Tiny game design crash course Core loop ("what does the player do every 5 seconds?"), constraints breed creativity, scope ("your idea ÷ 4"). Show examples of jam games made in 48 hours.

0:30–1:00 — Brainstorm with constraints Roll the constraint dice (or draw cards). Every game must satisfy the camp constraint set:

  • One screen OR one mechanic OR one button (pick at least one)
  • Playable in under 3 minutes
  • Buildable with skills from Days 1–2 (movement, collision, pickups, score, timers)

Solo silent brainstorm (8 min, sticky notes) → cluster ideas on the wall → dot-vote.

1:00–1:30 — Form teams + pitch Teams of 3–4 form around the top ideas. Each team writes its one-sentence pitch ("You are a ___ who ___ until ___") and gets it approved by an instructor. Instructor's job here: cut scope ruthlessly.

1:30–2:15 — Paper prototype Draw the screen, the player, the obstacles. Walk through 30 seconds of play out loud. Another team plays the paper version and asks questions.

2:15–3:00 — Project setup + roles Create the team Godot project, build the main scene skeleton, get a player moving on screen before the block ends. Assign rotating roles:

  • Lead/Producer — keeps the task list, watches scope
  • Engineer(s) — scripts and scenes
  • Artist/Sound — sprites, palette, audio (Kenney, jsfxr/BeepBox)
  • Playtest lead — runs tests, logs bugs

Sharing work on one project: simplest is one "main" computer + others build pieces (scenes, art, sounds) and transfer via Google Drive. I thought about using GitHub but its too complicated for this and everyone would need an account or we would have to have all this setup before hand.

#Open Studio (optional)

Start building. Teams that move fast: get the core mechanic playable today.

#Day 4 (Thu) — Production Day

📓 Full lesson + student reference: Day 4 - Production Day

Goal: A playable Minimal Viable Project (MVP) by end of teaching block. Ugly is fine; playable is "mandatory".

#Teaching Block

0:00–0:10 — Stand-up Each team, 60 seconds: done yesterday / doing today / what's blocking us.

0:10–0:20 — MVP talk Define MVP: player can play, win or lose, and restart. That's it. Everything else is polish. Have each team write their MVP checklist on an index card; tape it to the monitor.

0:20–2:20 — Build sprint Instructors float and unblock. Run on-demand micro-lessons at a side table as needs emerge (typical requests: scene switching for a title/game-over screen, score labels, restart button, background music, simple enemy AI).

2:20–2:50 — Mandatory playtest exchange Teams swap machines and play each other's MVPs for 10 minutes, then deliver: 2 things that work, 1 confusing thing, 1 suggestion. Teams triage feedback into fix tomorrow vs. cut.

2:50–3:00 — Scope check Each team crosses off anything on their list they won't finish by tomorrow's 3 PM build deadline. Instructor signs off.

#Open Studio (optional)

This is the high-value work session — expect most teams to stay. Hard rule: no new features after today. Tomorrow is polish only.

#Day 5 (Fri) — Polish + Arcade Showcase

📓 Full lesson + student reference: Day 5 - Polish and Showcase

Goal: Finish, present, celebrate. Showcase is 4:00–6:00 PM so parents can attend after work (adjust as needed) — which makes Friday the one day where Open Studio time is effectively part of the schedule.

#Teaching Block (morning)

0:00–0:10 — Stand-up + freeze warning Feature freeze is already in effect. Today: bug fixes, title screen, sounds, juice (screen shake, particles — only if stable).

0:10–2:00 — Polish sprint Must-haves before the showcase: title screen with the game's name and team names, a way to restart, no crashes in 3 minutes of play.

2:00–2:30 — Presentation prep Each team preps a 3–4 minute presentation: game name + one-sentence pitch, live demo (a teammate plays while another talks), one thing that was hard and how they solved it, one thing they'd add with another week.

2:30–3:00 — Dress rehearsal Each team runs its presentation once for the room. Fix timing, decide who talks/who plays.

#Afternoon (before doors open)

  • Final bug fixes only — no new anything
  • 3:00 — hard deadline: working builds on the demo machine(s) (export or run-from-editor)
  • 3:00–4:00: set up arcade stations (team game + Day 2 remixes), voting tickets, certificates; teams take a break

#🕹️ Arcade Showcase — 4:00–6:00 PM

  • 4:00–4:15 — Doors open, parents arrive, games on attract-mode at stations
  • 4:15–5:00 — Team presentations (3–4 min each + applause)
  • 5:00–5:45 — Open arcade: all games playable at stations, parents and campers vote with tickets for superlatives — Most Creative, Best Feel, Funniest, Best Title Screen. Every team wins something.
  • 5:45–6:00 — Awards, certificates, where to keep going (Godot docs, GDQuest, 20 Games Challenge, itch.io game jams), and how to take projects home (USB/email/itch.io upload)
