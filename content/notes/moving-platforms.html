Platforms that slide back and forth, elevators, falling platforms, conveyor belts. The classic way to make a platformer level feel alive instead of static. Builds on Platformer Physics and Node2D and Marker2D.

#Use AnimatableBody2D, not StaticBody2D

This is the whole trick and it saves an hour of pain.

NodeResult
StaticBody2D you move in codeThe player doesn't ride it. Platform slides out from under them, or squishes them into the ceiling.
CharacterBody2DWorks, but you're re-implementing what the engine already does.
AnimatableBody2D✅ Built exactly for this. Moves where you tell it and carries whatever is standing on it.

AnimatableBody2D is a physics body designed to be moved by code or an AnimationPlayer while still pushing other bodies properly. Its Sync to Physics property (on by default) is what makes the player ride along.

#The platform scene

Scene → New Scene → Other Node → AnimatableBody2D, save as moving_platform.tscn.

#Version A: between two markers (most flexible)

In your level scene, add two Marker2Ds — PointA and PointB — and drag them where the platform should travel.

extends AnimatableBody2D

@export var point_a: NodePath
@export var point_b: NodePath
@export var speed = 100.0
@export var wait_time = 0.5

var target: Vector2
var other: Vector2
var waiting = false

func _ready():
	target = get_node(point_b).global_position
	other  = get_node(point_a).global_position
	global_position = other

func _physics_process(delta):
	if waiting:
		return
	global_position = global_position.move_toward(target, speed * delta)
	if global_position.distance_to(target) < 1.0:
		var swap = target
		target = other
		other = swap
		if wait_time > 0:
			waiting = true
			await get_tree().create_timer(wait_time).timeout
			waiting = false

move_toward() walks a value toward a target at a fixed rate and stops exactly there — no overshoot. It's the same function Patrol Enemies uses.

The @export ... NodePath lines give you drag-and-drop slots in the Inspector: drop in PointA and PointB and the platform is configured. Drag one platform scene into a level four times, point each at different markers, and you have four platforms with zero extra code.

⚠️Parent the markers to the level, not the platform

A marker parented to the platform moves with it, so the platform chases a target it can never reach and drifts off screen forever.

#Version B: no markers, just a distance

Fewer moving parts, good for a team in a hurry.

extends AnimatableBody2D

@export var travel = Vector2(200, 0)   # (200,0) horizontal, (0,-200) elevator
@export var speed = 100.0

var start_pos: Vector2
var going_out = true

func _ready():
	start_pos = global_position

func _physics_process(delta):
	var target = start_pos + travel if going_out else start_pos
	global_position = global_position.move_toward(target, speed * delta)
	if global_position.distance_to(target) < 1.0:
		going_out = not going_out

Set travel in the Inspector per instance. (0, -300) makes an elevator; (200, 0) makes a slider.

#Version C: zero code (AnimationPlayer)

Add an AnimationPlayer child, new animation move, Loop on, Autoplay on. Key position at 0s and 2s at one end, and at 1s at the other end. Set the interpolation curve to Ease In-Out for a smooth glide.

Genuinely the best option for a team with a strong artist and a nervous programmer — and it's the option Godot's AnimatableBody2D was designed around.

#Variations

A falling platform — stand on it, it shakes, then drops:

extends AnimatableBody2D

var triggered = false

func _on_top_detector_body_entered(body):
	if triggered or not body.is_in_group("player"):
		return
	triggered = true
	var t = create_tween().set_loops(6)
	t.tween_property(self, "position:x",  3, 0.05).as_relative()
	t.tween_property(self, "position:x", -3, 0.05).as_relative()
	await t.finished
	sync_to_physics = false        # required before free-falling
	while true:
		global_position.y += 600 * get_physics_process_delta_time()
		await get_tree().physics_frame
		if global_position.y > 2000:
			queue_free()

Add a thin TopDetector Area2D just above the platform surface. The shake is a warning — a platform that falls with no telegraph feels unfair.

A one-way moving platform — check One Way Collision on the CollisionShape2D so you can jump up through it (CollisionShape2D).

A conveyor belt — a StaticBody2D with Physics Material Override → Friction 0, plus a nudge in the player's script while is_on_floor().

A crumbling platform — like the falling one, but queue_free() instead of dropping, with a fade-out tween.

A platform on a circular path:

@export var radius = 120.0
@export var rotation_speed = 1.0
var angle = 0.0
var center: Vector2

func _ready(): center = global_position

func _physics_process(delta):
	angle += rotation_speed * delta
	global_position = center + Vector2(cos(angle), sin(angle)) * radius

#Common problems

ProblemFix
Player doesn't move with the platformIt's a StaticBody2D — change it to AnimatableBody2D
Player jitters while ridingMove it in _physics_process, never _process. Confirm Sync to Physics is on.
Platform pushes the player into a wall and they vibrateGive the player a CapsuleShape2D and leave clearance at the end of the run
Platform drifts away foreverMarkers parented to the platform instead of the level
Player slides off a horizontal platformExpected in some engines — AnimatableBody2D handles it. If it persists, check the player is a CharacterBody2D using move_and_slide()
Jumping off feels weakKnown platformer quirk: the player doesn't inherit platform momentum. Usually fine; ignore it on Day 4.
