The Goomba: an enemy that walks back and forth between two points, forever. The player's job is to time their way past it (or stomp it). Builds on CharacterBody2D; the aggressive cousin is Homing Enemies, and Enemy States combines the two into one enemy that patrols until it spots you.

#The enemy scene

Same structure as the player:

Goomba          (CharacterBody2D)   Layer: mobs, Mask: world
├── Sprite      (AnimatedSprite2D)  ← a 2-frame "walk" animation sells it
└── Shape       (CollisionShape2D)

Save as goomba.tscn. See AnimatedSprite2D for setting up the walk frames.

#Two patrol points with Markers

The cleanest way to say "walk between here and here" is two Marker2D nodes you can see and drag in the editor.

In your Main/Level scene (not inside the Goomba!):

Main
├── Level        (TileMapLayer)
├── Player
├── Goomba       (instance of goomba.tscn)
├── PatrolA      (Marker2D)   ← drag to the left end of the route
└── PatrolB      (Marker2D)   ← drag to the right end
⚠️Markers must NOT be children of the Goomba

If the points are inside the enemy, they move with it — the Goomba chases its own feet and moonwalks off the map. Put them in the level, as siblings of the enemy.

Script on the Goomba root:

extends CharacterBody2D

@export var speed = 100
@export var gravity = 1200.0
@export var point_a: Marker2D   # drag PatrolA here in the Inspector
@export var point_b: Marker2D   # drag PatrolB here

var target: Marker2D

func _ready():
	target = point_b

func _physics_process(delta):
	# stick to the floor (delete these two lines for a top-down game)
	if not is_on_floor():
		velocity.y += gravity * delta

	# walk toward the current target
	var direction = sign(target.global_position.x - global_position.x)
	velocity.x = direction * speed
	move_and_slide()

	# close enough? turn around
	if abs(target.global_position.x - global_position.x) < 10:
		target = point_a if target == point_b else point_b

	# face the way we're walking
	$AnimatedSprite2D.flip_h = direction < 0

Line by line:

  • @export var point_a: Marker2D — after attaching the script, select the Goomba and drag PatrolA/PatrolB from the scene tree into the Inspector slots. Empty slots = instant crash on target.global_position.
  • sign(...) — returns -1 or 1: "is my target left or right of me?" Same trick as the Camera2D look-ahead.
  • < 10 — a 10-pixel "close enough" zone. Checking for exactly reaching the point fails — the enemy overshoots by a few pixels each frame and vibrates in place. Never compare positions with ==.
  • target = point_a if target == point_b else point_b — the swap: whichever point we reached, aim at the other one.
  • flip_h = direction < 0 — face the walk direction (AnimatedSprite2D).

Instance more Goombas and give each pair their own markers — every one can patrol a different route with zero code changes.

#Alternative: no markers, just a distance

Fewer nodes, less visual — walk patrol_distance pixels from wherever it starts, then turn around:

extends CharacterBody2D

@export var speed = 100
@export var patrol_distance = 150
var start_x = 0.0
var direction = 1

func _ready():
	start_x = global_position.x

func _physics_process(delta):
	velocity.x = speed * direction
	move_and_slide()
	if abs(global_position.x - start_x) > patrol_distance:
		direction *= -1
	$AnimatedSprite2D.flip_h = direction < 0

Good for scattering many enemies fast; the marker version is better when routes need precise placement. (Third option — turn around at walls with is_on_wall() — lives in Movement and Input.)

#Hurting the player

The Goomba body itself only collides with world, so touching the player does nothing yet. Add a Hurtzone Area2D child (Layer: none, Mask: player) with its own CollisionShape2D, connect body_entered:

func _on_hurtzone_body_entered(body):
	body.take_damage()   # the player decides the consequence — see Health and Lives

Same pattern as Hazards — the enemy reports the touch, the player's take_damage() handles lives/respawn/i-frames (Health and Lives).

#Stomping it (the full Goomba)

Jump on its head to squish it — the head is safe, the sides hurt. Shape placement does all the work:

Goomba
├── Sprite
├── Shape        (CollisionShape2D)
├── Hurtzone     (Area2D → thin shapes on the LEFT and RIGHT sides)
└── StompZone    (Area2D → thin shape across the TOP, Mask: player)
func _on_stomp_zone_body_entered(body):
	if body.velocity.y > 0:            # only counts if the player is falling
		body.velocity.y = -300         # bounce the player off the head
		$AnimatedSprite2D.play("squish")
		set_physics_process(false)     # stop walking
		$Hurtzone/CollisionShape2D.set_deferred("disabled", true)
		await $AnimatedSprite2D.animation_finished
		queue_free()
  • body.velocity.y > 0 — falling means stomping. Walking into the head zone sideways won't trigger it.
  • set_deferred("disabled", true) — disables the hurtbox safely during physics (setting it directly mid-collision throws an error).
  • The await line plays the squish animation before removal — see AnimatedSprite2D (one-shot animations). No squish animation? Replace the last three lines with queue_free().
  • Player bounce (-300) is the classic Mario feel — see Juice and Game Feel.
