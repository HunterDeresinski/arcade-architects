A signal is how one node says "hey, something just happened!" and another node reacts. It's Godot's version of "when this, do that."

Real examples:

  • A Timer fires its timeout signal → spawn an enemy (Spawning and Timers)
  • An Area2D fires body_entered → the player got hit (Area2D)
  • A Button fires pressed → start the game (Scene Switching)

#Connecting a signal in the editor (the easy way)

  1. Select the node that sends the signal (e.g. a Timer).
  2. In the Node dock (right side, next to Inspector), click the Signals tab.
  3. Double-click the signal (e.g. timeout).
  4. Pick the node whose script should react, click Connect.

Godot writes an empty function in that script for you. Fill it in:

func _on_timer_timeout():
	spawn_enemy()   # your code here

The function name _on_<node>_<signal> is just Godot's naming — you can keep it.

#Connecting a signal in code

Sometimes you make a node while the game runs (like a spawned enemy) and must connect by code:

var enemy = enemy_scene.instantiate()
enemy.body_entered.connect(_on_enemy_body_entered)
add_child(enemy)

#Making your own signal

extends Area2D

signal coin_collected     # declare it at the top

func grab():
	coin_collected.emit()  # announce it happened

Then anything connected to coin_collected runs. This is how you keep score from a coin without tangling your code together.

💡Mental model

Signals are like a doorbell. The button (sender) doesn't know or care who answers — it just rings. Anyone connected hears it and responds.
