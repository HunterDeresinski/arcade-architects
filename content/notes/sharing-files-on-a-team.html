🏠 Curriculum Map · Used on Day 3 - Design Day, Day 4 - Production Day

How a team of 3–4 works on one Godot project without GitHub. Decide your method on Day 3 before you start building.

#The method: one main computer + bring pieces in

GitHub is powerful but too heavy for one week (accounts, setup, merge conflicts). Instead:

  1. Pick one "main" computer. The Godot project lives here, and the Engineer builds in it. This is the source of truth.
  2. Everyone else makes pieces on their own machines — art, sounds, a sketched scene, a bit of script in a text file.
  3. Bring pieces to the main computer via a shared drive / USB / cloud folder, and the Engineer drops them into the project.

This avoids two people editing the same file and overwriting each other.

#Adding pieces to the project

  • Art & sound: copy the image/audio file into the project's folder (or drag it into the FileSystem dock). Asset Resources
  • A whole scene someone built: copy their .tscn and any files it uses into the project, then instance it (Scenes and Nodes).
  • A bit of code: paste it into the right script on the main computer (don't email whole .gd files around — copy the snippet).

#Back up every day (do not skip)

At the end of each day, copy the entire project folder to a USB or cloud drive. The project folder contains everything. Losing it the night before the showcase is the worst-case scenario.

  • A Godot project = one folder with a project.godot file inside. Copy the whole folder, not just one file.
