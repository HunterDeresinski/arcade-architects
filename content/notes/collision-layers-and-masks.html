The system that decides which things are allowed to touch which things. Every Area2D, CharacterBody2D, and StaticBody2D has these two settings. This note is the single source of truth for them — the other notes link here instead of repeating the table.

#The mantra

  • Layer = what am I? — the group this object belongs to.
  • Mask = what do I look at? — the groups this object reacts to.

A collision or overlap only happens if A's mask includes B's layer.

That's it. Everything below is applying that one rule.

❗It is not symmetric

A can see B without B seeing A. That's a feature, not a bug — it's how a coin notices the player without the player being shoved by the coin.

#Step 1: name your layers (do this once)

Project → Project Settings → Layer Names → 2D Physics. Naming them turns an unreadable grid of checkboxes into something you can actually reason about.

#NameWhat lives here
1playerthe player body
2mobsenemies, mobs, anything that hurts you by touch
3obstacleswalls, floor, TileMapLayer, Obstacles
4bulletsevery bullet, player-fired or enemy-fired (Making Bullets)
5hazardslava, spikes, saw blades (Hazards)
6pickupscoins, hearts, keys (Collectables)

Use this scheme for the whole camp. Every other note in this reference assumes it.

What this scheme buys you:

  • Player and mobs both stop at walls — both masks include obstacles.
  • The player doesn't physically shove mobs — the player's mask has no mobs. Touching an enemy is handled by a Hurtbox and a signal, so you decide what "getting hit" means.
  • Coins only react to the player, never to an enemy walking over them.
  • A bullet only hits what its mask says. Player bullets mask mobs; enemy bullets mask player. One layer, two behaviours — see Making Bullets.

#Step 3: how to actually set them

Select the node → Inspector → Collision. Two rows of checkboxes: Layer on top, Mask below. Hover any box and Godot shows the name you gave it in Step 1.

To set them in code (rarely needed, but useful for a bullet fired by either side):

set_collision_layer_value(4, true)   # I am on layer 4 (bullets)
set_collision_mask_value(2, true)    # I look at layer 2 (mobs)

The numbers are the layer numbers from the table, not bitmasks. false turns one off.

#The Hurtbox pattern

Moving solidly and detecting "I got hit" are two different jobs. Don't make one node do both — give the body a child Area2D whose only job is detecting:

Player               (CharacterBody2D)  Layer: player, Mask: obstacles
├── Sprite            (AnimatedSprite2D)
├── Shape             (CollisionShape2D)
└── Hurtbox           (Area2D)  Layer: none, Mask: mobs, hazards, bullets
    └── HurtShape     (CollisionShape2D)
func _on_hurtbox_area_entered(area):
	take_damage(1)   # see Health and Lives

A hurtbox receives damage. A hitbox deals it. Mobs get the mirror image: a body on layer mobs, and a hurtbox masking bullets.

#Debugging

💡Turn on the X-ray

Debug → Visible Collision Shapes, then run the game. Every shape draws as a cyan outline. Ninety percent of "collision isn't working" is solved in ten seconds by seeing that a shape is missing, tiny, or offset from the sprite.

SymptomCause
Walks through wallsThe wall's layer isn't in the walker's mask
Nothing happens on overlapMissing CollisionShape2D, or an empty Shape slot
Gets stuck on things it shouldn'tA mask box is checked that shouldn't be
Bullet kills the thing that fired itShooter's hurtbox masks its own bullet layer
Player shoves mobs aroundmobs is in the player's mask — uncheck it
