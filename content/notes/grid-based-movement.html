Moving one tile at a time instead of freely. This unlocks puzzle games — Sokoban, Bomberman, Snake, roguelikes, Pokémon-style overworlds.

💡The best genre for a 5-day camp

Puzzle games are finishable. There's no game feel to tune, no enemy AI to balance, no juice required — a puzzle either works or it doesn't. A team that builds ten good Sokoban levels ships a complete game. A team building a platformer ships one level and a wish list. If a team is anxious about scope on Day 3, point them here.

#The core idea

The player has a grid position (Vector2i(3, 5) = column 3, row 5) which is the truth, and a pixel position that animates to catch up. Movement is a series of discrete, validated steps — not continuous physics.

extends Node2D

const TILE_SIZE = 32

var grid_pos = Vector2i(0, 0)
var is_moving = false

func _ready():
	position = Vector2(grid_pos) * TILE_SIZE

func _unhandled_input(_event):
	if is_moving:
		return                      # ignore input mid-step

	var dir = Vector2i.ZERO
	if Input.is_action_just_pressed("move_right"):   dir = Vector2i.RIGHT
	elif Input.is_action_just_pressed("move_left"):  dir = Vector2i.LEFT
	elif Input.is_action_just_pressed("move_down"):  dir = Vector2i.DOWN
	elif Input.is_action_just_pressed("move_up"):    dir = Vector2i.UP

	if dir != Vector2i.ZERO:
		try_move(dir)

func try_move(dir):
	var target = grid_pos + dir
	if not is_walkable(target):
		return
	grid_pos = target
	animate_to(target)

func animate_to(target):
	is_moving = true
	var t = create_tween()
	t.tween_property(self, "position", Vector2(target) * TILE_SIZE, 0.12)
	await t.finished
	is_moving = false

Use Vector2i (integer vectors) for grid coordinates and Vector2 for pixels. Keeping them separate prevents a whole category of rounding bugs.

The is_moving guard makes movement feel deliberate and stops inputs queuing into a slide.

#Checking what's walkable with a TileMapLayer

@export var walls: TileMapLayer

func is_walkable(cell: Vector2i) -> bool:
	return walls.get_cell_source_id(cell) == -1     # -1 means empty

get_cell_source_id() returns -1 for an empty cell, so "no wall tile here" means you can walk. Drag your wall TileMapLayer into the export slot. Set the TileMapLayer's tile size to match TILE_SIZE.

#Sokoban: pushing boxes

The genre-defining mechanic, and it's about fifteen lines.

func try_move(dir):
	var target = grid_pos + dir

	if not is_walkable(target):
		return

	var box = box_at(target)
	if box:
		var behind = target + dir
		# a box can only be pushed into empty floor -- not a wall, not another box
		if not is_walkable(behind) or box_at(behind):
			return
		box.push_to(behind)

	grid_pos = target
	animate_to(target)

func box_at(cell: Vector2i):
	for box in get_tree().get_nodes_in_group("boxes"):
		if box.grid_pos == cell:
			return box
	return null

#Undo (do this — it's what makes a puzzle game playable)

A puzzle game without undo is a puzzle game where every mistake means restarting. Players quit instead.

var history = []

func record():
	var snapshot = {"player": grid_pos, "boxes": []}
	for box in get_tree().get_nodes_in_group("boxes"):
		snapshot["boxes"].append(box.grid_pos)
	history.append(snapshot)

func undo():
	if history.is_empty():
		return
	var s = history.pop_back()
	$Player.snap_to(s["player"])
	var boxes = get_tree().get_nodes_in_group("boxes")
	for i in boxes.size():
		boxes[i].snap_to(s["boxes"][i])

Call record() before every successful move. snap_to() sets both grid_pos and position with no tween.

Ten lines, and your game becomes forgiving enough that people finish levels. Best effort-to-quality ratio on this page.

#Snake

Same grid, different rules — the body is a list of cells:

var body = [Vector2i(5,5), Vector2i(4,5), Vector2i(3,5)]
var direction = Vector2i.RIGHT

func step():
	var head = body[0] + direction
	if head in body or not is_walkable(head):
		game_over()
		return
	body.push_front(head)
	if head == food_cell:
		spawn_food()          # grew -- don't remove the tail
	else:
		body.pop_back()
	redraw()

Drive step() from a repeating Timer rather than input — input only changes direction. That's the whole game.

#Turn-based enemies

The real payoff of a grid: enemies move only when you do. No reflexes, all planning.

func animate_to(target):
	is_moving = true
	var t = create_tween()
	t.tween_property(self, "position", Vector2(target) * TILE_SIZE, 0.12)
	await t.finished
	is_moving = false
	get_tree().call_group("enemies", "take_turn")   # now they move

A simple chaser that steps one tile toward you:

func take_turn():
	var to_player = player.grid_pos - grid_pos
	var step = Vector2i.ZERO
	if abs(to_player.x) > abs(to_player.y):
		step.x = sign(to_player.x)
	else:
		step.y = sign(to_player.y)
	if is_walkable(grid_pos + step):
		grid_pos += step
		create_tween().tween_property(self, "position", Vector2(grid_pos) * TILE_SIZE, 0.1)

That's a complete roguelike enemy.

#Common problems

ProblemFix
Player drifts off the grid over timeYou're adding to position directly. grid_pos is the truth; always recompute pixels from it
Holding a key slides the playerUse is_action_just_pressed, and keep the is_moving guard
Walks through wallsTileMapLayer tile size doesn't match TILE_SIZE, or the wrong layer is in the export slot
Boxes push through each otherMissing the box_at(behind) check
Movement feels sluggishTween duration too long — 0.10–0.15s is the sweet spot
Everything is off by half a tileTile origin is the corner, not the centre — offset the sprite, not the position
