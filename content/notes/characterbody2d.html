The go-to node for anything the player controls (or any enemy that walks around and hits walls). It's a physics body that you move with code — the engine handles the "don't walk through walls" part. Builds on Movement and Input and Area2D.

#What CharacterBody2D is (and isn't)

Godot has three kinds of 2D physics bodies:

  • StaticBody2D — never moves. Walls, floors, Obstacles. No script needed.
  • CharacterBody2D — moved by your code via move_and_slide(). Players, enemies.
  • RigidBody2D — moved by the physics engine (gravity, bouncing). Skip it for camp games — it fights you.

An Area2D is not a body — it detects overlaps but can't be blocked by anything. That's why the Day 1 Area2D player can't have solid walls (see Obstacles).

#Scene setup, step by step

  1. Scene → New Scene, click Other Node, pick CharacterBody2D. Rename it Player.
  2. Add a child: Sprite2D (or AnimatedSprite2D). Drag a texture into its Texture slot.
  3. Add a child: CollisionShape2D. In the Inspector, set Shape to a CapsuleShape2D (or Rectangle/Circle) and size it to roughly match the sprite.
  4. Save as player.tscn.
Player          (CharacterBody2D)   ← script goes here
├── Sprite      (Sprite2D or AnimatedSprite2D)
└── Shape       (CollisionShape2D)  ← must have an actual shape assigned
⚠️The yellow warning triangle

A CharacterBody2D with no CollisionShape2D (or a CollisionShape2D with an empty Shape) shows a ⚠️ in the Scene dock and won't collide with anything. Same #1 mistake as Area2D.

#Setting up input actions

Before writing movement code, name your inputs. Project → Project Settings → Input Map:

  1. Type move_left in the "Add New Action" box, click Add.
  2. Click the + next to the action, press the key (A or ←), click OK.
  3. Repeat for move_right, move_up, move_down (and jump if you need it — see Platformer Physics).

#Basic movement (top-down)

Attach a script to the Player root:

extends CharacterBody2D

@export var speed = 400

func _physics_process(delta):
	# get_vector reads all four actions and returns a normalized direction
	var direction = Input.get_vector("move_left", "move_right", "move_up", "move_down")
	velocity = direction * speed
	move_and_slide()

That's the whole thing. Notes:

  • velocity is built into CharacterBody2D — don't declare var velocity, it already exists.
  • move_and_slide() uses velocity automatically (no arguments) and slides along walls instead of stopping dead.
  • Input.get_vector() is already normalized — diagonals aren't faster. It replaces the four if statements from Movement and Input.
  • Movement goes in _physics_process, not _process — it runs in sync with the physics engine.

For jumping and gravity instead of top-down, see Platformer Physics.

#What people actually do with a CharacterBody2D

  • The player, top-down or platformer (Platformer Physics).
  • Walking enemies — a patroller that turns at walls, or a chaser that steers at you every frame.
  • Anything that must not pass through walls but isn't controlled by physics — an escort NPC, a pushable-but-scripted crate.

Three helpers you get for free after calling move_and_slide():

is_on_floor()    # standing on ground -- the heart of jumping
is_on_wall()     # touching a wall -- how a patroller knows to turn around
is_on_ceiling()  # bonked your head

And for reacting to what you hit:

for i in get_slide_collision_count():
	var c = get_slide_collision(i)
	print("bumped into ", c.get_collider().name)

#Collision layers and masks

Every physics body has a Layer ("what am I?") and a Mask ("what do I look at?"), set in Inspector → Collision. A collision happens only if A's mask includes B's layer.

The full scheme — the layer names to use, the layer/mask table for every scene type in this reference, the Hurtbox pattern, and the debugging table — lives in one place: Collision Layers and Masks. For a Day 1 or Day 2 game the defaults are fine; go read that note the first time something passes through a wall it shouldn't.

The short version for a player:

SceneLayerMask
Player (CharacterBody2D)playerobstacles
Player's Hurtbox (child Area2D)(none)mobs, hazards

Give the body a child Area2D named Hurtbox to detect damage. Moving solidly and noticing hits are two different jobs — don't make one node do both.
