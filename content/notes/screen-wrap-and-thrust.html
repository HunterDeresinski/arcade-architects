Asteroids movement: you rotate, you thrust forward, you drift, and you wrap around the screen edges. It's a completely different feel from the eight-directional movement in Movement and Input — and it's the single most arcade control scheme there is.

Arcade Architects, after all. If a team wants to build something that feels like it belongs in a cabinet, this is it.

#Rotate-and-thrust movement

The key difference: the direction you face and the direction you're travelling are not the same thing. That gap is the entire skill of the genre.

extends CharacterBody2D

@export var thrust_power = 500.0
@export var rotation_speed = 3.5
@export var max_speed = 600.0
@export var friction = 0.4          # 0 = true space, higher = more drag

func _physics_process(delta):
	# turning
	var turn = Input.get_axis("move_left", "move_right")
	rotation += turn * rotation_speed * delta

	# thrusting -- push in the direction the nose is pointing
	if Input.is_action_pressed("move_up"):
		velocity += Vector2.RIGHT.rotated(rotation) * thrust_power * delta
		$Flame.emitting = true
	else:
		$Flame.emitting = false
		velocity = velocity.move_toward(Vector2.ZERO, friction * 60 * delta)

	velocity = velocity.limit_length(max_speed)
	move_and_slide()
	wrap_screen()
  • Vector2.RIGHT.rotated(rotation) is the ship's facing direction as a unit vector. This assumes your sprite's nose points right at rotation 0 — draw it that way, or add - PI/2 to correct art that points up.
  • Adding to velocity rather than setting it is what creates momentum. You can be facing forward and still sliding backward, which is the whole game.
  • friction = 0 gives you true frictionless space — authentic, and much harder. Start around 0.4 and let playtesters decide (Playtesting).
  • $Flame is a particle emitter on the back of the ship. One line, and thrusting reads.

#Screen wrap

Fly off the left edge, appear on the right.

func wrap_screen():
	var screen = get_viewport_rect().size
	if global_position.x < 0:          global_position.x += screen.x
	elif global_position.x > screen.x: global_position.x -= screen.x
	if global_position.y < 0:          global_position.y += screen.y
	elif global_position.y > screen.y: global_position.y -= screen.y

Or the one-liner version:

func wrap_screen():
	var screen = get_viewport_rect().size
	global_position.x = wrapf(global_position.x, 0, screen.x)
	global_position.y = wrapf(global_position.y, 0, screen.y)

wrapf() wraps a float into a range — the same helper used for cycling letters in High Scores That Persist.

💡The pop-in problem

The ship vanishes at one edge and appears at the other with nothing in between, which looks abrupt. The proper arcade fix is to draw a second copy of the ship near the opposite edge while it's straddling the boundary. It's fiddly. The cheap fix that's almost as good: wrap based on the sprite's centre but let it travel half a sprite-width past the edge before wrapping, so it exits fully before reappearing.

#Shooting forward

Bullets inherit the ship's facing, not the ship's velocity (Making Bullets):

func shoot():
	var b = BulletScene.instantiate()
	get_tree().current_scene.add_child(b)
	b.global_position = $Muzzle.global_position       # see Node2D and Marker2D
	b.rotation = rotation
	b.velocity = Vector2.RIGHT.rotated(rotation) * bullet_speed

Give the bullet the same wrap_screen() and it circles the screen too — which is very Asteroids, and occasionally lets you shoot yourself in the back. That's a feature.

#Splitting asteroids

The genre's other signature mechanic. One asteroid scene, an exported size, and it spawns smaller copies of itself when destroyed:

extends CharacterBody2D

const AsteroidScene = preload("res://asteroid.tscn")

@export var size = 3                  # 3 = big, 2 = medium, 1 = small
@export var speed = 100.0

func _ready():
	var angle = randf() * TAU
	velocity = Vector2.RIGHT.rotated(angle) * speed
	scale = Vector2.ONE * (size * 0.35)

func _physics_process(_delta):
	move_and_slide()
	wrap_screen()

func destroy():
	if size > 1:
		for i in 2:
			var a = AsteroidScene.instantiate()
			a.size = size - 1
			a.speed = speed * 1.3        # smaller pieces move faster
			get_parent().add_child(a)
			a.global_position = global_position
	Global.add_score(size * 10)
	queue_free()

A scene that instantiates itself is a genuinely lovely idea to show students — one scene file produces the entire cascade of an asteroid field breaking apart. TAU is a full circle in radians (2π), which is nicer than typing 2 * PI.

Win when no asteroids remain:

if get_tree().get_nodes_in_group("asteroids").is_empty():
	next_wave()

#Other games with this movement

  • Asteroids — the original
  • Lunar Lander — same thrust, add gravity, land gently
  • Spacewar! — two ships, a star pulling both in (Two-Player and Gamepad)
  • Agar-style drifting — thrust toward the mouse instead of facing
  • A submarine or hovercraft — heavy friction, slow turning, feels weighty

Thrust toward the mouse instead of a fixed facing:

rotation = global_position.angle_to_point(get_global_mouse_position())
