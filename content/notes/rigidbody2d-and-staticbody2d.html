The other two physics bodies. CharacterBody2D gets the spotlight because you control it, but these two do real work: StaticBody2D is every wall in your game, and RigidBody2D is what the Day 1 mobs actually are.

#StaticBody2D

The simplest node in Godot. Add it, give it a CollisionShape2D, done — no script, ever.

Wall            (StaticBody2D)
├── Sprite       (Sprite2D)
└── Shape        (CollisionShape2D)

Layer obstacles, mask (none) — see Collision Layers and Masks. A wall doesn't need to look for anything; the things that move look for it.

#What people actually do with it

  • Level geometry. Though if you have more than a handful of walls, paint a TileMapLayer instead — it generates all this for you.
  • One-way platforms. Select the CollisionShape2D → check One Way Collision. Jump up through, land on top. Two clicks.
  • Slippery ice / conveyor belts. Inspector → Physics Material Override → New PhysicsMaterial2D → set Friction to 0.
  • A bouncy wall. Same Physics Material, Bounce to 1.0. Only affects RigidBody2D; a CharacterBody2D needs the code in Bouncing Ball.
  • Solid hazards. A spike block is a StaticBody2D (blocks you) plus a child Area2D (hurts you). See Hazards.
💡Moving a StaticBody2D

You can change its position in code, but it won't push anything — the player will be shoved out or squished unpredictably. If it moves and carries the player, you want AnimatableBody2D (Moving Platforms).

#RigidBody2D

You don't move a RigidBody2D. You nudge it and let the engine take over — gravity, momentum, bouncing, spinning, all for free. That freedom is exactly why it's a bad fit for a player character: you ask it to stop, and it argues.

#The Day 1 mob

Dodge the Creeps mobs are RigidBody2Ds. They get one velocity at spawn and drift forever:

extends RigidBody2D

func _ready():
	# gravity_scale is set to 0 in the Inspector so they drift instead of falling
	linear_velocity = Vector2(randf_range(150, 250), 0).rotated(rotation)

That gravity_scale = 0 is the setting students always miss when they add a new mob type — the mob falls straight off the bottom of the screen. See Homing Enemies for the version that chases you instead.

#Pushing it around

apply_central_impulse(Vector2(0, -400))   # one instant kick (a jump, an explosion)
apply_central_force(Vector2(200, 0))      # continuous push, every frame
linear_velocity = Vector2(300, 0)         # set speed outright -- use sparingly
angular_velocity = 5.0                    # spin

#What people actually do with it

  • Physics crates the player can shove around.
  • A bomb or grenade you toss with apply_central_impulse and let arc naturally.
  • Falling debris for juice (Juice and Game Feel).
  • A real bouncing ball — Bounce 1.0, Gravity Scale 0, Linear Damp 0, one impulse at start. This is the lazy way to build Pong; Bouncing Ball shows the controllable way and explains why you'd want it.
⚠️Don't set position on a RigidBody2D

Teleporting one fights the physics engine and causes jitter or tunneling. If you must move it directly, you probably wanted a CharacterBody2D.

#Detecting a hit

RigidBody2D doesn't report collisions by default. Inspector → check Contact Monitor, set Max Contacts Reported to 4 or more, then connect body_entered (Signals). Forgetting this pair of settings is the classic "my RigidBody signal never fires" bug.
