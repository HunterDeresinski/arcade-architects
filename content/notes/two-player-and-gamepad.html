Two people playing at once, and controller support. Bouncing Ball builds a two-player Pong; this is the general technique for any game.

#Why bother

At a showcase, a two-player game draws a crowd and a single-player game draws a line. People wait their turn for one and gather around the other. If a team is undecided about their pitch on Day 3, this is a strong argument for versus or co-op.

#The core idea: one scene, exported action names

Don't build player1.tscn and player2.tscn. Build one player scene whose input action names are @exported, then set them per instance in the Inspector.

extends CharacterBody2D

@export var up_action    = "p1_up"
@export var down_action  = "p1_down"
@export var left_action  = "p1_left"
@export var right_action = "p1_right"
@export var fire_action  = "p1_fire"

@export var speed = 400.0

func _physics_process(_delta):
	var dir = Input.get_vector(left_action, right_action, up_action, down_action)
	velocity = dir * speed
	move_and_slide()

	if Input.is_action_just_pressed(fire_action):
		shoot()

Drag the scene in twice, change five strings on the second one, done. One script to fix bugs in, two players.

#Adding controllers

An action can hold several events at once — keyboard and gamepad. In the Input Map, click + next to an action and choose Joypad Button or Joypad Axis.

The key field is Device:

  • Device 0 = first controller, Device 1 = second, and so on.
  • Device -1 / "All Devices" = any controller. Fine for single-player, wrong for two-player — both players would move on either pad.

So for real two-player controller support: p1_* actions get gamepad events on Device 0, p2_* actions get the same buttons on Device 1.

#Analog sticks

Input.get_vector() already returns analog values, so a stick gives you smooth 0–1 movement for free. Add Joypad Axis → Left Stick events to your directional actions and it just works.

Deadzone (a field on each action, default 0.2) stops a worn stick from drifting. Raise it to 0.3 if a controller creeps on its own.

#Detecting connected controllers

func _ready():
	print("Controllers: ", Input.get_connected_joypads())

func _input(event):
	if event is InputEventJoypadButton or event is InputEventJoypadMotion:
		show_gamepad_prompts()
	elif event is InputEventKey:
		show_keyboard_prompts()

Swapping the button prompts on screen when a player picks up a controller is a small touch that reads as very polished.

Godot also emits a signal when a pad is plugged in mid-game:

func _ready():
	Input.joy_connection_changed.connect(_on_joy_changed)

func _on_joy_changed(device, connected):
	print("Device %d %s" % [device, "connected" if connected else "disconnected"])

#Rumble

Input.start_joy_vibration(0, 0.4, 0.7, 0.25)   # device, weak, strong, seconds

Fire it when the player takes damage (Health and Lives) or lands a hit. Costs one line and feels great — see Juice and Game Feel.

#Co-op vs versus

Versus is easier to design and better at a showcase. Pong, a shooting duel, a race, a king-of-the-hill. Scoring is obvious and matches end quickly, so the queue moves.

Co-op needs more thought — a shared Camera2D has to frame both players. The cheap fix is a fixed camera on one screen; the real fix is a camera that follows the midpoint and zooms out as they separate:

extends Camera2D

@export var p1: NodePath
@export var p2: NodePath

func _process(_delta):
	var a = get_node(p1).global_position
	var b = get_node(p2).global_position
	global_position = (a + b) / 2.0
	var dist = a.distance_to(b)
	zoom = Vector2.ONE * clamp(700.0 / max(dist, 1.0), 0.5, 1.0)

Simplest co-op of all: keep both players on one screen and don't let them leave it. Clamp their positions to the viewport and skip cameras entirely.
