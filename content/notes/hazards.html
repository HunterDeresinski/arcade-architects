Things that hurt the player on touch — lava, spikes, poison pools, saw blades. The counterpart to Obstacles (which block but don't hurt). Builds on Area2D and CharacterBody2D.

#The idea

A hazard is just an Area2D that calls take_damage() on the player. It doesn't block movement — the player can walk into lava (that's the point). If you also want it solid (a spiky wall), you combine it with a StaticBody2D — see the spike block at the bottom.

Hazards live on the hazards layer and mask player. The full layer scheme for the whole camp is in Collision Layers and Masks — set it up once there and every note in this reference lines up.

#Basic lava pit

New scene: Area2D root named Lava:

Lava            (Area2D)            Layer: hazards, Mask: player
├── Sprite      (Sprite2D)          ← lava art, stretched over the pit
└── Shape       (CollisionShape2D)  ← RectangleShape2D covering the danger zone

Connect the Area2D's body_entered signal (Signals) and attach:

extends Area2D

func _on_body_entered(body):
	body.take_damage()

That's the whole script. Because the mask is player only, body can never be a mob or a bullet — no checks needed, same trick as Making Bullets.

💡Make the shape slightly smaller than the art

Pull the CollisionShape2D in a few pixels from the lava's visual edge. Players feel like they died fairly when the hitbox is forgiving; pixel-perfect lava feels cheap. This is a real game-design trick, not a hack.

#The player side: taking the hit

The hazard's whole job is to report the damage. The player decides what that means — lose a heart, respawn, game over. That logic belongs in one place, on the player, so every hazard, mob, and bullet in your game shares it.

That code lives in Health and Lives: take_damage(), invincibility frames, hearts, respawning, and checkpoints. Build it once there and every hazard on this page works.

The two things worth repeating here, because hazards are where they bite hardest:

1. Invincibility frames are not optional for hazards. Standing in lava fires the damage call every physics frame — sixty hits a second, three hearts gone instantly. The if invincible: return guard in Health and Lives is what makes a hazard feel fair instead of broken.

2. Reset velocity on respawn. Without velocity = Vector2.ZERO, a player who fell into a pit respawns still travelling at full falling speed and immediately dies again.

If your team hasn't built the health system yet, the two-line version is enough to get a hazard working today:

# minimal version in the player script — upgrade to Health and Lives later
func take_damage(_amount = 1):
	global_position = get_tree().current_scene.get_node("SpawnPoint").global_position
	velocity = Vector2.ZERO

#Lava in a tile-based level

Three ways to make tiles dangerous, from simplest to most flexible. Pick one.

#Option A: paint visuals, stretch an Area2D (simplest)

Paint the lava tiles as pure visuals (no physics on those tiles), then stretch one Lava Area2D from above over the whole pool. One hazard, one shape, easy to see and debug. Best when you have a few big pools.

#Option B: solid hazard tiles (spikes you stand on)

Hazard tiles that are solid — the player lands on them and gets hurt. Good for spike strips and thorn floors.

  1. Add a second TileMapLayer node named HazardTiles next to your Level layer (see TileMapLayer → Multiple layers). Keeping hazards on their own node is the trick — it lets the player tell lava apart from ordinary ground.
  2. Give it its own TileSet (or reuse the same one) with a physics layer whose Collision Layer = hazards (TileMapLayer → Making tiles solid (collision)).
  3. Select the HazardTiles node → Node dock → Groups → add it to a group called hazards.
  4. Make sure the player's mask includes hazards so move_and_slide() actually collides with these tiles.
  5. Paint your spikes on HazardTiles, normal ground on Level.

Player side — after move_and_slide(), ask what we bumped into:

func _physics_process(delta):
	# ...movement code, then move_and_slide(), then:
	for i in get_slide_collision_count():
		var collision = get_slide_collision(i)
		if collision.get_collider().is_in_group("hazards"):
			take_damage()
  • get_slide_collision_count() / get_slide_collision(i) — everything move_and_slide() touched this frame.
  • get_collider() returns the node we hit — the HazardTiles layer — and the group check identifies it. Walls on Level aren't in the group, so they stay harmless.

#Option C: walk-in hazard tiles with Custom Data (real lava)

Lava you can walk into — not solid, hurts while you're in it. This is the "proper" Godot way and it scales to any number of pools with zero extra nodes.

Mark the tiles:

  1. Select your Level TileMapLayer → Inspector → expand Tile Set → Custom Data Layers → Add Element. Name it hazard, Type bool.
  2. Open the TileSet panel (bottom) → Select mode → click a lava tile → expand Custom Data → check hazard.
  3. Repeat for every dangerous tile. Give lava tiles no physics layer — they shouldn't block.

Check the tile the player is standing in:

# in the player script
@export var level: TileMapLayer   # drag the Level node here in the Inspector

func _physics_process(delta):
	# ...movement code, then:
	var tile_pos = level.local_to_map(level.to_local(global_position))
	var tile_data = level.get_cell_tile_data(tile_pos)
	if tile_data and tile_data.get_custom_data("hazard"):
		take_damage()
  • to_local() then local_to_map() — converts the player's world position into "which grid cell am I in" (TileMapLayer → Placing tiles from code (optional)).
  • get_cell_tile_data() returns null on empty cells — that's what the if tile_data and ... guards against. Skip the guard and you crash the first time the player is over an empty cell.
  • global_position is the player's center. For a tall character, check the feet instead: global_position + Vector2(0, 20) (half the collision shape's height).
  • This runs every frame you're in lava — the invincibility frames in Health and Lives are not optional here.

#Variants

Spikes (hurt + solid): combine both nodes — a StaticBody2D block (Obstacles) with a hazard Area2D child covering just the pointy top:

SpikeBlock       (StaticBody2D)     Layer: obstacles, Mask: (none)
├── Sprite
├── Shape        (CollisionShape2D) ← the solid block
└── Hurtzone     (Area2D)           Layer: hazards, Mask: player
    └── Shape    (CollisionShape2D) ← thin strip along the spikes only

Same one-line body.take_damage() script on the Hurtzone. The player can stand beside it safely and gets hurt only from the spiky side.

Moving saw blade: put the lava script on an Area2D and animate its position — simplest way is an AnimationPlayer keyframing position back and forth, or the patrol pattern from Movement and Input adapted to an Area2D (position.x += speed * direction * delta).

Damage-over-time pool (lose a life every second you stand in it) — use body_entered/body_exited plus a Timer instead of one-shot damage; only reach for this if the design really needs it.

⚠️"The lava doesn't hurt me"

Check, in order: (1) Does the Area2D have a CollisionShape2D with an actual shape? (2) Is the signal connected? (3) Hazard mask includes player's layer? (4) Does the player script actually have a take_damage() function (Health and Lives)? — the error Invalid call. Nonexistent function 'take_damage' means it doesn't.
