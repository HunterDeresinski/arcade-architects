How to keep score, lives, and settings alive across scene changes. The partner note to Scene Switching.

A script that is always loaded, in every scene, and never destroyed. It's the answer to "how do I keep the score when I go to the next level?" — a question Scene Switching raises three times and defers to an instructor. This is that answer.

#The problem it solves

change_scene_to_file() destroys the old scene and everything in it. Your score variable lived in the old scene. It's gone.

Level 1  (score = 250)  →  change scene  →  Level 2  (score = 0)  😞

An autoload lives outside all scenes, so it survives the switch.

#Setting one up

  1. Create a new script anywhere in the project. Call it global.gd. Don't attach it to anything.
  2. Project → Project Settings → Globals → Autoload tab.
  3. Click the folder icon, pick global.gd.
  4. Node Name: Global. Click Add.

That's it. Now Global works from any script in the project, with no $ path and no get_node().

❗Name it something obvious

Global, GameState, or GameManager. The Node Name field is what you type in code — if you name it g you will regret it by Thursday.

#A game state autoload

# global.gd
extends Node

signal score_changed(new_score)
signal lives_changed(new_lives)

var score = 0
var high_score = 0
var lives = 3
var current_level = 1

func add_score(amount):
	score += amount
	if score > high_score:
		high_score = score
	score_changed.emit(score)

func lose_life():
	lives -= 1
	lives_changed.emit(lives)
	if lives <= 0:
		game_over()

func game_over():
	get_tree().change_scene_to_file("res://game_over.tscn")

func reset_game():
	score = 0
	lives = 3
	current_level = 1

Use it from anywhere — no path, no reference, no setup:

# in a coin script (see Collectables)
Global.add_score(10)

# in the player (see Health and Lives)
Global.lose_life()

# on the game over screen
$FinalScore.text = "Final Score: %d" % Global.score

#Wiring the UI to it

Each scene connects to the autoload's signals when it loads:

# in your Main scene
func _ready():
	Global.score_changed.connect(_on_score_changed)
	_on_score_changed(Global.score)      # show the current value right away

func _on_score_changed(value):
	$UI/ScoreLabel.text = "Score: %d" % value

That second line matters — connecting only tells you about future changes, so call it once manually to display what's already there.

⚠️Always reset before a new game

Global never resets by itself. Without Global.reset_game() on your title screen's Start button, the second playthrough begins with the first one's score and zero lives. This is the #1 autoload bug.

#What belongs in an autoload

Good:

  • Score, lives, current level, unlocked abilities
  • Settings — music volume, difficulty
  • Saved data (High Scores That Persist)
  • A music player that keeps playing across scene changes (below)

Bad:

  • The player node, or anything visual — those belong in the scene
  • Everything, because it's convenient. An autoload that knows about all of your game becomes the tangle every bug lives in

#Music that survives scene changes

The classic use, and it's three lines. Make an autoload scene instead of a bare script: a Node root with an AudioStreamPlayer child, saved as music.tscn, then autoload the scene file.

extends Node

func play(track: AudioStream):
	if $Player.stream == track and $Player.playing:
		return                     # already playing this -- don't restart it
	$Player.stream = track
	$Player.play()

Without this, changing scenes restarts your music from the top every time — which sounds broken.

#The simpler alternative (use it when you can)

You often don't need an autoload at all. If your levels are just swapped tilemaps inside one persistent Main scene — the pattern in Scene Switching — the player and score are never destroyed, so nothing needs saving.

Rule: if you can avoid changing scenes, avoid the autoload too. Reach for this when you genuinely have separate Title / Game / Game Over scenes and need something to survive between them.
